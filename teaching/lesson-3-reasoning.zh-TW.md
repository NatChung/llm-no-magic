# Lesson 3 — Tab ③ 推理:thinking 就是把思考寫成 token

> English: [lesson-3-reasoning.md](./lesson-3-reasoning.md)

## 學習目標
1. 知道 thinking mode = model 先吐 `<think>…</think>` 思考 token、再吐答案
2. 體會同一個 model,「有沒有空間想」對答案正確率的影響
3. 知道什麼任務值得開 thinking(拿捏題/多步推理),什麼不用(查表式短答)

## Hook 問答(先問,不給答案)
- 「爸爸有 3 顆蘋果,兒子多他 2 顆。請問兒子幾顆?— 這題你覺得 0.6B 小 model 直接答,會對嗎?」
- 「你用過 ChatGPT 的『思考中…』模式嗎?你覺得它在做什麼?」

## ⚠️ Prompt 標點陷阱(帶課前必讀)

蘋果題**對標點極度敏感**,送錯版本整段對照會破功。`agent/server.py` 的 `/completion`
寫死 `temperature: 0` → **完全 deterministic,沒有抽樣**,同一 prompt 永遠同一串輸出,
所以「多按幾次總會錯一次」是不存在的,只能靠送對字。

| 送進去的字 | 直答模式的答案 |
|---|---|
| `爸爸有3顆蘋果,兒子多他2顆。請問兒子幾顆?`(**半形** `,` `?`、數字不空格) | **1 顆** ❌ 要用這版 |
| `爸爸有 3 顆蘋果,兒子多他 2 顆。請問兒子幾顆?`(全形 `,` `?` 或加空格) | **5 顆** ✅ 對照破功 |

半形版:model 設 x、列 `x + 2 = 3` → 解出 1(把「兒子多他2顆」讀反)。
全形版:model 自己列「1. 2.」步驟 → `3 + 2 = 5` — 等於**在可見答案裡自己做了 chain-of-thought**,
沒有 `<think>` 也照樣答對。

**守則**:一律用 `POST /drive` 送字,或叫學員**不要改輸入框**(`frontend/index.html:145`
預填的就是半形版)。學員自己手打很容易打成全形。

備援(想要更穩的答錯,都會答 `2` — 沒空間寫步驟就抓題目最後出現的數字交差):
- 題目後面加「只回答一個數字。」← **最推薦**,最貼近真實 production prompt
- system 加「直接給答案,不要解釋、不要列步驟。」
- prefill 助手開頭「兒子有」

試過**無效**的(0.6B 照樣答對,不用浪費時間):反向題(爸爸比兒子多2)、三步題(再加媽媽)。

## Demo 段落

### 段落 1 — 直答(錯)
- **接上一課**:輸入框裡的「爸爸有3顆蘋果,兒子多他2顆。請問兒子幾顆?」就是 Lesson 2 收尾那題 —
  切過來時自動帶進來了。上一課它「會回答」但答錯(算成兒子 = 1);這一課就來看怎麼讓它答對
- 預告:「直答模式 = 我們強塞一個空的 <think></think>,model 沒空間想、直接吐答案。猜它答幾顆?」
- 驅動:`POST /drive {"tab":"3","user":"爸爸有3顆蘋果,兒子多他2顆。請問兒子幾顆?","mode":"direct"}` → 頁面自動切到 Tab ③ 渲染
- 讀回應:它會設 x、列出 `x + 2 = 3`,解出**兒子 1 顆** — 把「兒子多他2顆」讀反了 →
  旁白:第一步就設錯方程,後面全順著錯下去;它只是在接龍「最順的算式」

### 段落 2 — 用 thinking(通常對)
- 預告:「同一題,這次讓它把推理寫出來。注意畫面會多一個『完整回覆(含 <think>)』區。」
- 驅動:`POST /drive {"tab":"3","user":"爸爸有3顆蘋果,兒子多他2顆。請問兒子幾顆?","mode":"thinking"}` → 頁面渲染 thinking 區 + 最終答案
- 讀回應:thinking-content 填入 `<think>…</think>`、`</think>` 後的 generated-text 是最終答案(對出 5)→ 旁白:看 thinking 區 — 推理真的是一個一個 token 寫出來的,不是隱形魔法;寫完 `</think>` 後才出最終答案,而且對了
- **值得指出來**:它會在 `<think>` 裡**自己把「會不會是我讀反了?」這個可能性提出來再推翻**
  (「有沒有可能『多他2顆』指的是其他意思?…但題目明確說儿子比爸爸多2顆」)。直答模式沒空間
  做這件事,所以第一步設錯方程就沒救了。差別不是聰明度,是**有沒有地方讓它自我檢查**
- 小提醒:0.6B 的 thinking 內容常吐簡體字(「儿子」「苹果」),先跟學員說一聲免得被問

## 學員動手
讓學員改數字(爸爸 7 顆、兒子少他 3 顆…)兩種模式各跑一次;體會 thinking 慢但穩。

## 揭曉與回顧
- 對照 Hook 預測:你猜對了嗎?差別不是 model 變聰明,是**給了它把推理寫成 token 的空間**
- 連回 Hook A:法律、賠償這類拿捏題,開 thinking 更穩;法律紅線要明寫(例:「不得違反 XX 條」)—
  但該給的知識(SOP)還是要給,thinking 不能補知識缺口
- **收尾接龍(帶出下一課)**:換一題「現在幾點?」,**兩種模式各跑一次**(先收預測:
  哪種模式答得出來?):
  - 先直答:`POST /drive {"tab":"3","user":"現在幾點?","mode":"direct"}` — 沒空間想,
    通常直接編一個時間或秒答不知道
  - 再 thinking:`POST /drive {"tab":"3","user":"現在幾點?","mode":"thinking"}` — 盯著
    thinking 區看:model 會認真推理,在裡面自己講「我這裡沒有實體時鐘…我要怎麼知道現在
    幾點?」,最後只能**憑空假設 / 編一個時間 / 承認不知道**
  - 旁白:對比蘋果題 — 蘋果題答案所需的資訊都在題目文字裡,thinking 有救;這題的答案
    **根本不存在**於權重或上下文,直答編、thinking 想再久也拿不到 → **兩條路都死,
    它需要一個工具**。記住這句「現在幾點?」,下一課同一句會自動帶到下一個分頁,那裡它會
    真的去拿時間 → Lesson 4
  - **不要爆雷**:這裡只預告「它會真的拿到時間」,**不要**講機制(`<tool_call>`、client
    真的執行、結果塞回)— 那是 Lesson 4 段落 1 的揭曉高潮;提前講掉,「模型怎麼可能拿到
    真實時間?!」的懸念就沒了(就算這場學員已經看過 Tab ④,也照樣留白)

## 常見學員問題
- 「thinking 的內容可信嗎?」— 它是真實影響答案的 token,但也可能想錯;重要結論仍要核
- 「為什麼不每題都開?」— 慢、貴;查表式短答沒收益
